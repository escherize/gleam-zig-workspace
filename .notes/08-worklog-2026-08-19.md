## Discoveries

### zig 0.16 stdlib is not the zig you remember
- "writergate": `std.fs.File` is gone; stderr goes through
  `std.debug.lockStderr(&buffer)` -> `.file_writer.interface`. General
  file writers need an `Io` instance — `std.Io.Threaded.init_single_threaded`
  works for synchronous CLI use.
- `std.crypto.random` is gone. Seeded `std.Random.DefaultPrng` from
  `std.Io.Clock.now(.awake, io)` (Clock has no `.monotonic`; members are
  `real/awake/boot/cpu_process/cpu_thread`).
- `std.Io.Writer.Allocating` is the allocating writer.

### zig the language shapes codegen structurally
- One namespace per file: a local named like any file-scope declaration
  is a shadowing **error**. All generated locals are `@"v$name"`, lifted
  params `@"p$N"`, env `@"env$"`. Raw identifiers `@"..."` dodge keyword
  collisions and allow `$`.
- Unused locals error AND pointless discards error (`_ = x` when `x` is
  used later). Codegen does exact usage analysis; sound because rendered
  names are unique per function (`v$name$N`).
- Unused block labels error: clause blocks are only labelled when a
  pattern or guard can actually `break` to them.
- Union field access on the wrong tag is a runtime safety panic — pattern
  conditions chain `and` short-circuits so tag checks guard field reads.

### the JavaScript target is a quirk baseline, not ground truth
- JS echo prints `2` for the float `2.0` (`isSafeInteger` check runs
  before the float branch — JS can't tell Int from Float). zig prints
  `2.0`, matching Erlang. The harness tolerates this.
- stdlib maps `int.to_float` to `identity` on JS (ints are floats
  there). On zig that produced a union-tag crash; needs a real
  `@floatFromInt` conversion. Audit every `identity` external when
  porting stdlib to a target with a real type distinction.
- Wilson's-theorem primality is wrong on BOTH non-Erlang targets, each
  differently: 20!+ overflows — i64 wraps, f64 loses precision. Only
  bignums are exact. Overflow-sensitive programs cannot be
  cross-target-compared.

### compiler-fork mechanics
- `Definition` iteration: typed modules store `TypedDefinitions` as
  categorised vecs (imports/constants/custom_types/type_aliases/functions),
  not a flat list.
- The pattern typer pre-orders constructor arguments, so positional
  `fields[i]` access is correct even for labelled patterns.
- `RecordUpdate` arrives from the typer pre-desugared into a constructor
  call with implicit accessor arguments — codegen only needs to bind the
  updated record when `updated_record_assigned_name` is `Some`.
- Dependencies compile with `TargetSupport::NotEnforced`; only the root
  package must fully support the target. This is what makes incremental
  stdlib porting possible at all.
- Module caches are bitcode-serde; adding `Implementations` fields is
  fine (caches are compiler-version-keyed) but touches ~15 insta
  snapshots.

### performance
- Rewriting `prelude.zig` every build bumps its mtime and invalidates
  zig's entire build cache: 8s warm builds. A content-hash stamp file
  (`.prelude-<hash>`) restored 1.2s. Generalises: never touch generated
  files whose content is unchanged.

## Decisions

- **Target name `zig`** (user call), knowing it bakes the emission
  language into `@external` annotations; C-emission fallback would force
  a rename.
- **Uniform boxed `Value` union** rather than typed emission: mirrors
  the JS target's dynamic representation, defers monomorphisation, and
  keeps the Perceus pass simple. Revisit for unboxing after phase 3.
- **Sequential clause checks instead of porting decision.rs** (2,546
  lines): the type checker has already proven exhaustiveness, so
  fallthrough is `unreachable` and first-match-wins is semantically
  correct. Slower, massively simpler; decision trees are an optimisation
  for later.
- **Wrapping i64 arithmetic**: other targets never overflow (bignums /
  f64); zig debug builds panic on overflow, which would make arithmetic
  target-visibly crash. `+%` etc. trade silent wrap for no-crash.
- **Constants as zero-arg functions**, re-evaluated per use: constant
  values allocate, zig comptime can't. Immutable values make
  re-evaluation semantically invisible.
- **Module constants/labels/records**: variant identity is
  `(name, arity)` via name string compare — sound within a well-typed
  program because different types never meet in one match.
- **StringTree = plain string**, dict = insertion-ordered assoc list,
  graphemes = codepoints, case/trim ASCII-only — all marked `ponytail:`
  with upgrade paths in `gleam_stdlib.zig`.
- **Stack-overflow parity accepted**: deep non-self-tail recursion
  segfaults on zig exactly where JS throws RangeError (Ackermann). The
  JS target already accepts this contract.

## Blockers hit and cleared

- `@target(zig)` parse: `expect_target` had a hardcoded name list
  separate from strum — third place a target name must be registered
  (enum, `parse_external_attribute`, `expect_target`).
- `TimeoutExpired.stdout` is bytes even with `text=True` (Python quirk);
  crashed the sweep once.
- Background sweeps: 120s/target timeouts made by-design-infinite
  rosetta programs (count-forever) burn 4 min each; 20s cap fixed sweep
  time (~7 min for 86 programs).
- `gleam run --target zig` reports exit 0 for a segfaulted program —
  exit-code propagation through the runner needs a look (open).
